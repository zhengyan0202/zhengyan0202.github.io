Token是什么

2026年03月29日
AI

Token到底是什么

Token（官方中文译名为“词元”）是模型处理信息的基本单位

Context Window 模型一次能够处理的最大信息量
DeepSeek R1 一次最多能处理12.8万(128K)个Token 它不是12.8万个字也不是12.8个词

Token是怎么生成的？它和字、词之间是什么关系？

先了解“大模型的基本工作原理”
大模型本质上是一个巨大的数学函数，内部全是矩阵运算 输入的是数字，输出的也是数字。
它不理解输入的文字，中间需要一个“翻译官”-Tokenizer

Tokenizer负责编码和解码两个环节

  • 编码：文字 → 数字

    1. 切分：把输入文字切分成一个一个最小的单位，切出来的碎片就叫Token
    2. 映射：会把每一个Token映射为对应的数字，这个数字叫Token ID

  • 解码：数字 → 文字
    映射：把Token ID映射为Token

Token 与 Token ID是一一对应关系，Token是文字，Token ID是数字，所表达的内容是一样的。一句话就变成了一串Token ID列表，然后Tokenizer把它传给模型，模型内部进行运算，吐出来一个Token ID，Tokenizer再次登场将Token ID翻译为Token，解码环节不需要切分，模型每次只给出一个Token，没输出完的话继续输出第二个Token等等。

例如，句子“我喜欢苹果！”可能会被拆分为 ["我", "喜欢", "苹果", "！"] 这4个Token。

Tokenizer的实现算法

  • Unigram
    Google
  • BPE
    OpenAI和Anthropic

BPE的训练过程：大致就是从一堆文章里面能找出哪些文字经常在一起使用，把这些经常一起使用的字合起来作为一个Token。生成两个产物：

  • 词表：记录Token和Token ID的表
  • 合并规则

1个Token ≈ 1.5~2个汉字
1个Token ≈ 4个英文字母或0.75个英文单词

AI核心概念

2026年03月28日
AI

一、底层引擎LLM

核心定义与架构

  • LLM全称：Large Language Model (大语言模型) ，简称大模型
  • 底层架构：基于Transformer (2017年Google团队在论文《Attention is All You Need》中提出)
  • 工作原理：本质是文字接龙游戏，通过预测下一个概率最高的词生成连续文本

发展里程碑

时间 事件 意义
2017年 Transformer架构提出 奠定大模型基础技术
2022年底 GPT-3.5发布 首个达到可用级别的大模型
2023年3月 GPT-4发布 大幅提升AI能力天花板
2023年后 Claude、Gemini等模型涌现 AI赛道有OpenAI独角戏变为多强竞争

二、数据处理单元：Token

核心特性

  • 定义：大模型处理文本的最小单位，通过Tokenizer（分词器）将文本切分为片段
  • 编码过程：分为两步–1.文本切分为Token 2.映射为Token ID（数字）
  • 解码过程：将Token ID还原为文本（无需切分步骤）

Token与自然语言单位的关系

语言单位 与Token的关系 示例
中文词语 非一一对应，可能被拆分 “程序员”→“程序”+“员”
英文单词 常见词语通常一应一个Token “hello”→ 1个Token
复杂单词 可能被拆分 “helpful”→“help”+“ful”
特殊字符 可能需要多个Token表示 “✅️”→ 3个Token

量化参考

  • 1个Token ≈ 0.75个英文单词
  • 1个Token ≈ 1.5-2个汉字
  • 40Token ≈ 60-80万汉字或30万英文单词

三、临时记忆体：Context

核心概念

  • 定义：大模型每次处理任务时接收的信息总和，相当于模型的“临时记忆”
  • 组成部分：用户问题、对话历史、当期输出Token、工具列表、System Prompt等
  • 容量限制：有Context Window（上下文窗口）定义，即最大可处理的Token数量

主流模型Context Window对比

模型 Context Window （Token） 约合汉字数量
GPT-5.4 105万 约157.5万
Gemini 3.1 Pro 100万 150万
Claude Opus 4.6 100万 150万

突破Context Window限制的方案

  • RAG技术（检索增强生成）：从知识库中抽取与问题相关的片段，仅将关键信息送入模型，降低Token消耗

四、指令交互：Prompt

定义与分类

  • Prompt：给大模型的问题或指令，决定模型输出质量
  • Prompt分类：
    • User Prompt：用户输入的具体任务（如：帮我写一首诗）
    • System Prompt：开发者后台配置的人设与做事规则（如“你是一个耐心的数学老师，当学生提问你数学问题时，不要直接给答案，而是要一步一步引导学生思考，帮助他们理解解题思路”）

五、外部能力扩展：Tool

核心作用

  • 定义：大模型调用外部函数，使其能够感知和影响外部环境
  • 解决痛点：弥补大模型无法获取实时信息（如天气）、计算能力有限等弱点

工作流程

  1. 用户提问→平台转发（含工具列表）
  2. 大模型分析→生成工具调用指令
  3. 平台执行调用→获取结果
  4. 大模型整理结果→自然语言输出

角色分工

角色 职责
大模型 选择工具、生成参数、归纳结果
工具 执行集体功能（如查询天气）
平台 转发消息、执行工具调用

六、工具标准化：MCP

  • 全称：Model Context Protocol（模型上下文协议）

  • 本质：理解为统一的工具介入标准，解决不同平台工具接入规范不统一的问题。

    比如：OpenAI、Anthropic、Google三个平台各自有接入规范，用一个要写一个接入规范，所以想搞一个统一的技术规范标准。
    就像手机都统一用type c充电口统一标准

  • 价值：工具开发者只需按MCP规范开发一次，即可在所有支持MCP的平台使用（类比手机Type-C接口）

七、自主决策系统：Agent

  • Agent定义：能够自主规划、自主调用工具，持续工作直至完成用户任务的系统
  • 核心能力：多步骤推理、工具选择、流程控制
  • 代表产品：Claude Code、Codex、Gemini CLI等
  • 典型构建模式：React、Plan and Execute等

八、任务定制：Agent Skill

核心功能

  • 定义：给Agent的说明文档，包含任务规划、执行步骤、输出格式等
  • 结构：
    • 元数据层：名称（name），描述（description）
    • 指令层：目标、执行步骤、判断规则、输出格式、示例

技术实现

  • 存储形式：Markdown文档（文件名必须为“SKILL.md”）
  • 存放位置：特定目录（如Claude Code找到用户目录的“.claude/skills”文件夹）
  • 加载机制：尽在用户问题与技能名称/描述相关时加载完成命令

九、概念体系关联

![概念体系层级关系]
LLM（核心引擎）→ Token（数据单位）→ Context（记忆空间）→ Prompt（交互接口）→ Tool（外部能力）→ MCP（工具标准）→ Agent（决策系统）→ Agent Skill（任务定制）

补充细节

  • Transformer架构：虽由Google提出，但由OpenAI通过GPT系列引爆应用
  • Token切分原理：基于BPE（字节编码）算法，模型自主学习的文本切分规则
  • Agent Skill高级特性：支持运行代码、引用资源，采用渐进式披露机智节省Token
  • RAG技术：通过检索相关片段而非全文，有效解决Context Window限制问题

浅析Vue diff算法

2026年01月28日

Vue 的 diff 算法是其虚拟 DOM 机制的核心，旨在通过高效对比新旧虚拟 DOM 树的差异，以最小的代价更新真实 DOM，从而解决频繁操作真实 DOM 带来的性能瓶颈。

🎯 为什么需要 Diff 算法？

直接操作真实 DOM 是一个昂贵的过程。每次修改都可能触发浏览器的重排（Reflow）和重绘（Repaint），如果频繁进行全量更新，会导致页面卡顿，严重影响性能。

Diff 算法的解决方案是：

  1. 使用虚拟 DOM (VNode)：用一个轻量级的 JavaScript 对象来描述真实 DOM 的结构。
  2. 计算最小差异：当数据变化时，生成新的 VNode 树，并通过 diff 算法对比新旧两棵树，找出差异。
  3. 批量更新：将计算出的差异（补丁）一次性应用到真实 DOM 上，最大化地复用已有节点，最小化 DOM 操作次数。

🧠 Diff 算法的核心前提

为了将传统树对比算法 O(n³) 的时间复杂度优化到 O(n)，Vue 的 diff 算法基于以下三个关键假设：

  • 同层比较：只对比同一层级的节点，不考虑跨层级的节点移动。如果一个节点从父容器移动到了子容器，算法会直接销毁旧节点并创建新节点。
  • 类型判断：如果两个节点的标签名（tag）不同，则认为它们是不同的树，直接销毁旧节点并创建新节点。
  • Key 的唯一性：通过 key 属性来唯一标识节点，帮助算法快速、准确地找到可复用的节点。

⚙️ Vue 2 的双端 Diff 算法

Vue 2 采用的是双端比较算法，其核心思想是通过四个指针同时从新旧子节点列表的首尾两端向中间收缩，进行交叉对比，以快速找到可复用的节点。

  • 四个指针：

    • oldStartIdx / oldEndIdx：指向旧子节点列表的头部和尾部。
    • newStartIdx / newEndIdx：指向新子节点列表的头部和尾部。

  • 比对顺序：

    1. 头头比对：比较 oldStart 和 newStart。
    2. 尾尾比对：比较 oldEnd 和 newEnd。
    3. 头尾交叉比对：比较 oldStart 和 newEnd。
    4. 尾头交叉比对：比较 oldEnd 和 newStart。

  • 处理流程：

    • 如果以上任意一种比对成功（节点类型和 key 相同），则认为节点可复用，进行 patch 更新，并移动相应的指针。
    • 如果四种比对都失败，则会利用 key 在旧列表中查找是否存在可复用的节点。如果找到则移动节点，否则就创建一个新节点。
    • 这个过程会一直持续，直到新旧列表的指针相遇，最后处理剩余的节点（新增或删除）。

🚀 Vue 3 的快速 Diff 算法

Vue 3 在 Vue 2 的基础上进行了重大优化，引入了快速 Diff 算法，进一步提升了性能。

  • 预处理优化：

    1. 前置处理：从头部开始，同步对比新旧节点，直到遇到第一个不相同的节点。
    2. 后置处理：从尾部开始，同步对比新旧节点，直到遇到第一个不相同的节点。
      通过这两步，可以快速跳过首尾大量未变化的节点，将需要处理的范围缩小到中间的乱序部分。

  • 最长递增子序列 (LIS)：
    对于中间剩余的乱序节点，Vue 3 会采用最长递增子序列算法。该算法可以计算出最少需要移动多少个节点，从而以最少的操作完成 DOM 更新。例如，在列表排序时，算法会找出位置相对正确的最长节点序列，只移动不在此序列中的节点。

📊 Vue 2 与 Vue 3 Diff 算法对比

特性 Vue 2 Vue 3
算法类型 双端比较 快速 Diff + 最长递增子序列
时间复杂度 O(n) O(n)
预处理优化 无 有（前置+后置）
移动优化 依赖交叉比对和查找 使用最长递增子序列，移动次数更少

💡 开发实践：为什么 v-for 需要 key？

key 是 diff 算法高效、准确工作的关键。

  • 没有 key：Vue 会采用“就地复用”策略，即默认新旧列表的节点是按顺序一一对应的。当列表发生插入、删除或排序时，这种策略会导致节点被错误复用，可能引发组件状态错乱（例如，输入框的值保留给了错误的项）。
  • 使用 key：key 为每个节点提供了唯一的身份标识。diff 算法可以根据 key 精确地判断一个节点是新增、删除还是仅仅移动了位置，从而保证组件状态的正确性和渲染性能。

因此，在 v-for 循环中，务必使用一个稳定且唯一的标识（如后端返回的 id）作为 key，避免使用数组的 index。

Vue采用的思想是 同级比较、深度递归、双端遍历

同级比较：

同级比较只的是只对比两个相同层级的VNode，如果两者不一样了， 就不在去diff它们的子节点，更不会跨层级比较，而是直接更新它。这是因为在我们平时的操作很少出现将一个DOM节点进行跨层级移动，比如将原来的父节点移动到它子节点的位置上、所以diff算法就没有为这个极少数的情况专门去跨层级diff，毕竟为此得不偿失。这也是diff算法事件复杂度能从O(n^3)优化到O(n)的原因之一。

深度递归：

深度递归指的是比较两个虚拟DOM时采用深度优先的先序遍历策略，先比较完一个子节点后， 就去比较这个子节点的子孙节点，都递归完后再遍历它的兄弟节点。
为什么要使用深度优先遍历，广度优先遍历不行么？深度优先遍历使用到的是栈结构， 进行深度递归的时候，栈中保存的是当前节点的父元素和祖先元素，栈中存储的最大节点个数就是DOM数最大的层级数。而广度优先宾利使用的是队列结构，进行广度递归的时候，队列中保存的是下一层的节点，队列中存储的最大节点个数就是DOM数最大的层级节点数。而在通常情况下，一个DOM数的层级数是会小于它的层级节点数的，所以使用深度优先遍历占用的空间和消耗会更小些。

双端比较：

双堆比较指的是在diff新旧节点时，使用了四个指针分为四种比较法，当然还有最后一种通过key比较的。

  • oldStartIdx表示旧Vnode从左边开始diff的节点，初始值为第一个子节点；
  • oldEndIdx表示旧Vnode从由边开始diff的节点，初始值为第一个子节点；
  • newStartIdx表示新Vnode从左边开始diff的节点，初始值为第一个子节点；
  • newEndIdx表示新Vnode从由边开始diff的节点，初始值为第一个子节点；
  • oldStartIdx与newSnewStartIdx比较
  • oldStartIdx与newSnewEndIdx比较
  • oldEndIdx与newSnewStartIdx比较
  • oldEndIdx与newSnewEndIdx比较
  • key比较

对于新旧子节点， 其中一个遍历完，退出比较，剩下的子节点不是新增就是删除。
