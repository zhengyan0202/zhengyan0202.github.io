浅析Vue diff算法

2026年01月28日

Vue 的 diff 算法是其虚拟 DOM 机制的核心，旨在通过高效对比新旧虚拟 DOM 树的差异，以最小的代价更新真实 DOM，从而解决频繁操作真实 DOM 带来的性能瓶颈。

🎯 为什么需要 Diff 算法？

直接操作真实 DOM 是一个昂贵的过程。每次修改都可能触发浏览器的重排（Reflow）和重绘（Repaint），如果频繁进行全量更新，会导致页面卡顿，严重影响性能。

Diff 算法的解决方案是：

  1. 使用虚拟 DOM (VNode)：用一个轻量级的 JavaScript 对象来描述真实 DOM 的结构。
  2. 计算最小差异：当数据变化时，生成新的 VNode 树，并通过 diff 算法对比新旧两棵树，找出差异。
  3. 批量更新：将计算出的差异（补丁）一次性应用到真实 DOM 上，最大化地复用已有节点，最小化 DOM 操作次数。

🧠 Diff 算法的核心前提

为了将传统树对比算法 O(n³) 的时间复杂度优化到 O(n)，Vue 的 diff 算法基于以下三个关键假设：

  • 同层比较：只对比同一层级的节点，不考虑跨层级的节点移动。如果一个节点从父容器移动到了子容器，算法会直接销毁旧节点并创建新节点。
  • 类型判断：如果两个节点的标签名（tag）不同，则认为它们是不同的树，直接销毁旧节点并创建新节点。
  • Key 的唯一性：通过 key 属性来唯一标识节点，帮助算法快速、准确地找到可复用的节点。

⚙️ Vue 2 的双端 Diff 算法

Vue 2 采用的是双端比较算法，其核心思想是通过四个指针同时从新旧子节点列表的首尾两端向中间收缩，进行交叉对比，以快速找到可复用的节点。

  • 四个指针：

    • oldStartIdx / oldEndIdx：指向旧子节点列表的头部和尾部。
    • newStartIdx / newEndIdx：指向新子节点列表的头部和尾部。

  • 比对顺序：

    1. 头头比对：比较 oldStart 和 newStart。
    2. 尾尾比对：比较 oldEnd 和 newEnd。
    3. 头尾交叉比对：比较 oldStart 和 newEnd。
    4. 尾头交叉比对：比较 oldEnd 和 newStart。

  • 处理流程：

    • 如果以上任意一种比对成功（节点类型和 key 相同），则认为节点可复用，进行 patch 更新，并移动相应的指针。
    • 如果四种比对都失败，则会利用 key 在旧列表中查找是否存在可复用的节点。如果找到则移动节点，否则就创建一个新节点。
    • 这个过程会一直持续，直到新旧列表的指针相遇，最后处理剩余的节点（新增或删除）。

🚀 Vue 3 的快速 Diff 算法

Vue 3 在 Vue 2 的基础上进行了重大优化，引入了快速 Diff 算法，进一步提升了性能。

  • 预处理优化：

    1. 前置处理：从头部开始，同步对比新旧节点，直到遇到第一个不相同的节点。
    2. 后置处理：从尾部开始，同步对比新旧节点，直到遇到第一个不相同的节点。
      通过这两步，可以快速跳过首尾大量未变化的节点，将需要处理的范围缩小到中间的乱序部分。

  • 最长递增子序列 (LIS)：
    对于中间剩余的乱序节点，Vue 3 会采用最长递增子序列算法。该算法可以计算出最少需要移动多少个节点，从而以最少的操作完成 DOM 更新。例如，在列表排序时，算法会找出位置相对正确的最长节点序列，只移动不在此序列中的节点。

📊 Vue 2 与 Vue 3 Diff 算法对比

特性 Vue 2 Vue 3
算法类型 双端比较 快速 Diff + 最长递增子序列
时间复杂度 O(n) O(n)
预处理优化 无 有（前置+后置）
移动优化 依赖交叉比对和查找 使用最长递增子序列，移动次数更少

💡 开发实践：为什么 v-for 需要 key？

key 是 diff 算法高效、准确工作的关键。

  • 没有 key：Vue 会采用“就地复用”策略，即默认新旧列表的节点是按顺序一一对应的。当列表发生插入、删除或排序时，这种策略会导致节点被错误复用，可能引发组件状态错乱（例如，输入框的值保留给了错误的项）。
  • 使用 key：key 为每个节点提供了唯一的身份标识。diff 算法可以根据 key 精确地判断一个节点是新增、删除还是仅仅移动了位置，从而保证组件状态的正确性和渲染性能。

因此，在 v-for 循环中，务必使用一个稳定且唯一的标识（如后端返回的 id）作为 key，避免使用数组的 index。

Vue采用的思想是 同级比较、深度递归、双端遍历

同级比较：

同级比较只的是只对比两个相同层级的VNode，如果两者不一样了， 就不在去diff它们的子节点，更不会跨层级比较，而是直接更新它。这是因为在我们平时的操作很少出现将一个DOM节点进行跨层级移动，比如将原来的父节点移动到它子节点的位置上、所以diff算法就没有为这个极少数的情况专门去跨层级diff，毕竟为此得不偿失。这也是diff算法事件复杂度能从O(n^3)优化到O(n)的原因之一。

深度递归：

深度递归指的是比较两个虚拟DOM时采用深度优先的先序遍历策略，先比较完一个子节点后， 就去比较这个子节点的子孙节点，都递归完后再遍历它的兄弟节点。
为什么要使用深度优先遍历，广度优先遍历不行么？深度优先遍历使用到的是栈结构， 进行深度递归的时候，栈中保存的是当前节点的父元素和祖先元素，栈中存储的最大节点个数就是DOM数最大的层级数。而广度优先宾利使用的是队列结构，进行广度递归的时候，队列中保存的是下一层的节点，队列中存储的最大节点个数就是DOM数最大的层级节点数。而在通常情况下，一个DOM数的层级数是会小于它的层级节点数的，所以使用深度优先遍历占用的空间和消耗会更小些。

双端比较：

双堆比较指的是在diff新旧节点时，使用了四个指针分为四种比较法，当然还有最后一种通过key比较的。

  • oldStartIdx表示旧Vnode从左边开始diff的节点，初始值为第一个子节点；
  • oldEndIdx表示旧Vnode从由边开始diff的节点，初始值为第一个子节点；
  • newStartIdx表示新Vnode从左边开始diff的节点，初始值为第一个子节点；
  • newEndIdx表示新Vnode从由边开始diff的节点，初始值为第一个子节点；
  • oldStartIdx与newSnewStartIdx比较
  • oldStartIdx与newSnewEndIdx比较
  • oldEndIdx与newSnewStartIdx比较
  • oldEndIdx与newSnewEndIdx比较
  • key比较

对于新旧子节点， 其中一个遍历完，退出比较，剩下的子节点不是新增就是删除。
